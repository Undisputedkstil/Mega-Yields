# Reliable Vercel deployment without redesign

## Audit findings
- The current site has eight pages: Home, About, Produce, Operations, Partnerships, Contact, Privacy and Terms. All use TanStack routing and page-specific search/social metadata.
- `/sitemap.xml` is generated by a server handler. Server error handling and authentication helpers also exist.
- No active content page currently calls the database or an authenticated server function. Existing Lovable Cloud connections and database data must remain untouched.
- The enquiry form currently only displays a success message; it does not email or save enquiries. This is an existing limitation, not something deployment will fix.
- The likely Vercel 404 cause is an incorrect deployment target/output configuration. The actual Vercel project settings and deployment logs have not been inspected, so the cause is not yet confirmed.

## Supported approach
Lovable requires TanStack Start and does not support replacing it with React Router or a plain React + Vite application inside this project. Keep the existing architecture and configure its supported Vercel deployment instead. A plain React + Vite migration would need to happen outside Lovable, on a separate repository branch, with a static sitemap and deliberate handling of page-specific HTML metadata.

## Proposed changes
1. Create a recoverable source/configuration backup before deployment changes; do not alter Git branch state.
2. Configure the existing Vercel-capable deployment adapter without changing the site's design, copy, images, animations or URLs. Preserve Lovable's own deployment settings.
3. Document the Vercel build command, deployment output and required browser-safe environment variables. Never copy privileged keys into browser configuration.
4. Keep the sitemap, page metadata, contact form behavior and backend connections intact. Do not add a new enquiry delivery service in this task.
5. Check every existing page through navigation and direct refresh, inspect the sitemap, verify image loading and review the automatic production build results.
6. Provide the exact Vercel settings and any remaining deployment steps. Vercel-hosted behavior remains unverified until an actual deployment can be inspected.

## Technical details
- Keep TanStack Start v1, React 19, Tailwind v4 and the current route files.
- Use the installed Lovable Vite configuration's supported Nitro Vercel target, with Lovable's managed target retaining precedence in Lovable builds.
- Do not add a blanket SPA fallback over server endpoints or replace the generated route tree.
- No migration, page deletion, database changes or publishing occurs before this plan is approved.
